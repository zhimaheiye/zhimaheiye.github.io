Mumu模拟器开机自启动检测

问题描述

关于游戏日常的自动化，我之前一直采用这样的方式：将游戏脚本的启动程序快捷方式放在”shell:startup”文件夹下开机自启动，然后通过”启动模拟器并启动脚本“这一项使得脚本打开模拟器后自动连接运行。

游戏某次版本更新后，新版本的安装包无法在mumu12（旧版本编号）上运行，我不得不更新到当前的mumuV5，但这就导致了一个问题，这个版本的mumu模拟器无法稳定被清日常脚本启动。
主要的区别在于（模拟器这个我不懂，我只是根据自己的使用体验和理解来说）原来的版本是直接连接，新版本是在启动模拟器之后再单独启动其中不同的子设备。我可以为这个子设备新建快捷方式，如图所示

在把下面这个编号#0的模拟器快捷方式放进”shell:startup”文件夹后，某些时候是可以启动成功的，即脚本和模拟器都分别自启动然后连接起来，但并不稳定。
一方面是因为，原先的方式是由清日常脚本启动模拟器，方式是在脚本里设定模拟器的路径，脚本会等待模拟器60秒，并在连接成功后自动运行。但在后来的方式里模拟器并不是由脚本启动的，因此我只能选择启动脚本后直接运行，那么很多时候模拟器运行起来的时候脚本已经因为连接不上模拟器超时关闭了。
另一方面是有时候模拟器压根就启动不起来，原因不明，无法稳定复现。

比较好笑的是如果我在电脑刚启动的时候迅速点进来启动模拟器，那脚本就能连接上然后丝滑的运行，但这就跟我摆完挂机的愿望相违背了。
所以我需要另一个运行在模拟器和清日常脚本之外的程序，来检测和管理这两个的启动。

解决问题的过程

1.编写批处理文件

逻辑是先检测mumu模拟器是否在运行，等待30秒，确定在运行了之后再启动清日常脚本。脚本被设定了启动后自动连接模拟器并运行

批处理文件的代码可以查看这个文件：
run.bat

其中调用了另一个文件Start-MaaYuan.ps1
链接：Start-MaaYuan.ps1

过程中遇到的问题:正确检测mumu模拟器进程

问题描述：之前的代码里实际的模拟器没有被启动，但模拟器的主进程是开机自启的，因此脚本误认为模拟器已经启动了。修改的逻辑如下（是ai写的我不太懂）

1. 检测逻辑改进

  • 原来只检测 MuMuNxMain 进程，但后台服务常驻，会误判为”已运行”
  • 现在检测三层：
    • 主进程是否存在
    • 设备进程 MuMuNxDevice 是否运行（真正的模拟器）
    • 可见窗口 是否存在

2. 启动参数修复

  • 原来：MuMuNxMain.exe（无参数）→ 只打开管理器，不启动模拟器
  • 现在：MuMuNxMain.exe -v 0 → 正确启动模拟器实例

2.任务计划程序

  1. 按 Win + R，输入 taskschd.msc 回车/或者在搜索框里搜索”任务计划程序“
  2. 右侧点击 “创建基本任务”
  3. 设置名称，例如MaaYuanAutoStart
  4. 触发器：当特定用户登录时
  5. 操作：启动程序
  6. 程序/脚本：C:\Users\Administrator\.qclaw\workspace\Run-MaaYuan.bat（这里要修改为批处理脚本的实际路径
  7. 起始于（可选）：C:\Users\Administrator\.qclaw\workspace（脚本所在文件夹路径
  8. 完成前勾选 “打开属性对话框”
  9. 在属性里：
  • 常规 选项卡：勾选 “使用最高权限运行”
  • 触发器 选项卡：编辑 → 勾选 “延迟任务” → 设置为 1 分钟

但是这就引出了一个问题，我原先使用任务计划程序是在我平时的笔记本电脑上的，开机必定会登录，但这个清日常的台式机是挂机的不会每次都查看，因此需要去除掉”登录“这一步

3.去除登录

Win + R → regedit → 回车打开注册表
找到”HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon“
修改或确认以下项目的值：

  • AutoAdminLogon = 1
  • DefaultUserName = Administrator
  • DefaultPassword = （你的密码，没密码就留空字符串）

这样就能跳过登录页面直接进桌面了

博客配置与obsidian适配

1. 核心需求

在本地使用 Obsidian 编写文章，要求：

  • 链接兼容性：使用标准 Markdown 图片语法而非 Wiki 链接，确保 Hexo 正常渲染。
  • 附件管理：图片粘贴时自动存放至与笔记同名的子文件夹中。
  • 重命名流：粘贴图片时顺手重命名，保持文件整洁。

2. Obsidian 基础设置

首先需要关闭 Wiki 链接，强制 Obsidian 生成标准 Markdown 链接（即 [alt](path) 格式）。

  1. 打开 设置 -> 文件与链接 -> 使用 Wiki 链接：关闭。
  2. 附件默认存放路径：指定的附件文件夹（之后会通过插件来配置）。

3. 插件配置

Custom Attachment Location和consistent attachments and links
目前我本地的文件配置是可以正常运行的，但是在沙盒仓库里试图一步一步复现的时候失败了。暂时先放在这里，如果想使用这套方案可以直接复制hexo-obsidian这个仓库里的配置文件覆盖本地文件，这个我试了是可以用的

4. 实现后的工作流

  1. 截图或复制图片。
  2. 在笔记中粘贴：
    • 图片会自动创建并存入 ./笔记名/ 目录下。
  3. 重命名图片：
    • 粘贴后立即重命名，保持附件可读性。
  4. 推送博客：
    • 最终生成的语法是标准 MD 格式：{% asset_img "图片名.png" "图片名" %}。
    • 这种格式在 Hexo 开启 post_asset_folder: true 或直接使用相对路径引用时，可以完美在网页渲染。

obsidian使用技巧（缓慢更新中）

快速跳转至文件首尾

一个方法是使用快捷键 ctrl+end（开头就是ctrl+home）
另一个方法是安装插件，Remember Cursor Position，下次打开文件时会直接跳转到上次的光标处，实际使用的时候发现精确度不是太高，但够用了

多设备同步

百度网盘（强烈不建议）

百度网盘的同步空间更适合用来同步“保存后释放”的文件，而不是obsidian这种实时编辑的文件，仓库内的保存和网盘同步都会经常出错。
而且百度网盘会在同步冲突时新建一个冲突文件，类似：“文件1_冲突文件_时间戳”这种格式，但obsidian只会读取原命名文件，所以有的配置会同步出错，手动改很麻烦的

坚果云

把仓库文件夹右键设置同步，开机自启动之后就可以无感同步了。
每月只有1G上传流量，但对于绝大部分是文字的仓库来说是绰绰有余了

Remotely Save 插件 + S3 服务

配置稍微有点麻烦，当时是因为坚果云的流量用完了换到这个插件，实际使用上并没有明显比坚果云好很多，不过价格也很便宜

（未整理）

对于手机端的特殊说明

相册默认读取仓库下的文件，如果误删也会在仓库里被一并删除，解决方案是在仓库根目录下放一个”.nomedia”文件，这样相册就不会读取整个仓库下的图片文件了

图片附件

图片被粘贴进去的时候默认路径是根目录，但时间长了堆积起来，又全是以“Pasted image+时间戳”这种格式，难以区分

踩坑预警：Docker 代理配置导致的连接失败

在构建镜像时，可能会遇到类似 HTTP CONNECT: unexpected EOF xxx:443 的错误，导致拉取基础镜像失败。这通常是因为 Docker Desktop 的代理设置出现了问题。

解决办法：
如果你使用了 Clash 并且开启了 TUN 模式，可以直接把代理设置为本地回环地址。

  1. 打开 Docker Desktop 的 Settings -> Resources -> Proxies
  2. 开启 Manual proxy configuration
  3. HTTP 和 HTTPS 都填写：http://127.0.0.1:7897（端口号根据你的代理软件而定）
  4. Bypass 填写：localhost,127.0.0.1
  5. 点击 Apply & restart 重启 Docker 即可解决。
